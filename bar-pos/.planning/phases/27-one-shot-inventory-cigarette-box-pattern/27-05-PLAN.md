<objective>
Give the client layer a typed, validated surface over `open_units`: Zod schemas in `src/shared/lib/domain.ts` (the project's single source of truth per CLAUDE.md), the two new `ProductSchema` configuration fields, and one `open-unit` entity folder exposing a read query plus three RPC-backed mutation hooks.

Purpose: plans 27-06, 27-07, and 27-08 all bind to these names. Authoring them once, against RPC contracts already proven live by plans 27-02 through 27-04, means the UI layer never guesses a column name or a mutation signature. The mutation hooks call the RPCs rather than writing the table directly — D-07's invariant, D-08's message, and D-12's role guard all live server-side, so a client `.insert()`/`.update()` would bypass every one of them and would also be rejected by the `open_units_write_manager_admin` RLS policy for a bartender.

`open_units` and the two new `products` columns are not in `src/shared/lib/supabase.types.ts` yet. Per CLAUDE.md's documented workaround (and the identical treatment in `src/entities/inventory/model/queries.ts` lines 1-24 and `ModifierGroupEditor.tsx`), this plan uses a file-level `const db = supabase as any` with a file-level eslint pragma and a TODO naming the regeneration command. Regenerating `supabase.types.ts` is deliberately out of scope for this phase: it rewrites a 2000-plus-line generated file wholesale, and Phase 17 set the precedent of shipping the cast and regenerating as separate housekeeping.

Output: one `domain.ts` schema block, one entity folder, and unit coverage for the row/error mapping.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase response -> React component | Untrusted external data crosses here; without schema validation a malformed row reaches render code as `any` (the `db as any` cast removes every compile-time guarantee on this path). |
| client mutation input -> RPC | User-entered corrected counts and reasons cross here; the client check is a UX shortcut, the RPC guard is the control. |
