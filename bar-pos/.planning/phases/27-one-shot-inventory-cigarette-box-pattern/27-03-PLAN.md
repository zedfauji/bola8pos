**Scenario R1 — last-piece race (T-27-01).** Fixture: an `open_units` row seeded directly via the service-role client with `remaining_count = 1`, and the parent's `inventory.quantity_on_hand = 0` so no auto-open can mask the race. Fire two `deplete_for_order_item` calls for two distinct quantity-1 loose order items concurrently with `Promise.allSettled` through two separate authenticated clients. Assert: exactly one settled fulfilled and one rejected with a message containing `INVENTORY_NEGATIVE`; the final `remaining_count` is `0`, never a negative number; the row's `status` is `'exhausted'`; and exactly one `open_units` row exists for that product (no duplicate created by the loser's auto-open attempt).

**Scenario R2 — mid-sale unit-boundary crossing (SC-2, Pitfall 3).** Fixture: `units_per_package = 20`, an active unit seeded with `remaining_count = 1`, and `inventory.quantity_on_hand = 1` so exactly one fresh package is available. Sell a single order line of quantity 3 through `deplete_for_order_item`. Assert: the original unit ends `status = 'exhausted'` with `remaining_count = 0`; a second `open_units` row exists for the same product with `status = 'active'` and `remaining_count = 18` (20 minus the 2 carried over); `inventory.quantity_on_hand` is now `0`; and at no point does any row hold a negative count. Also assert exactly one row is `'active'` — the auto-transition must not leave two.

**Scenario R3 — exhaustion with zero packages, and the D-05 override.** Fixture: no active unit and `inventory.quantity_on_hand = 0`. First call `deplete_for_order_item(<fresh item>, 1, false)` and assert it rejects with a message containing `INVENTORY_NEGATIVE`, that no `open_units` row was created, and that `inventory.quantity_on_hand` is still `0`. Then call `deplete_for_order_item(<a second fresh item>, 1, true)` — the exact shape `src/features/override-negative-stock/model/useOverrideNegativeStock.ts` uses after manager PIN approval — and assert it resolves, a unit now exists, and `audit_logs` contains an `open_unit.override` row for it. This is the assertion that D-05's "same override mechanism as existing negative-stock handling" actually reaches open units through the shared chokepoint with no open-unit-specific override path.

**Scenario R4 — refund credit-back (`p_direction = -1`).** Fixture: an active unit with `remaining_count = 5` and `units_per_package = 20`. Call `deplete_for_order_item(<item with quantity 2>, -1, false)` and assert `remaining_count` becomes `7`.
