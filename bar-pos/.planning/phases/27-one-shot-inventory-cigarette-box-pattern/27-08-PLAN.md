<objective>
Land SC-3: an Open-Units tab inside the existing `/inventory` page that lists currently open units and exposes the three actions built in plan 27-07, with the correct/void controls individually role-gated.

Purpose: this is the last surface the phase needs and the one a human can actually look at. D-09 puts it inside `/inventory` rather than at a new route, which means `InventoryPagePanel.tsx` — which has no tabs today — grows a `Tabs` wrapper with its entire current body becoming the first tab. That refactor is the riskiest part of this plan: the page carries a stock table, a change log, a batch-adjustment dialog, and a CSV export, all of which must keep working untouched.

Gating is per-control, not per-tab. Both tabs are visible to bartender+ because D-11 requires bartenders to open units; only the correct and void controls are wrapped in `ProtectedAction action="adjust_inventory"` per D-12. `InventoryPagePanel.tsx` already imports `ProtectedAction` and uses it exactly this way for the existing Adjust and Export buttons, so the pattern is already in the file.

D-06 is a scope boundary enforced negatively: no low-remaining indicator, no threshold, no amber/destructive row styling driven by remaining count. The existing stock table's `rowHighlightClass` logic is package-level `low_stock_threshold` styling and must not be copied into the open-units table, however tempting the visual symmetry.

This plan ends the phase, so it also carries the human verification checkpoint for the full open-a-box-and-sell-through-it flow that no automated test in this phase covers end to end through the UI.

Output: one new widget, one component test, the tabs refactor, and i18n keys in both locales.
</objective>
