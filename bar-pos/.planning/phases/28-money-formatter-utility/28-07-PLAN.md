  <action>
    All four sites render a modifier price delta with an explicit sign. Replace each hand-built construction — a chosen sign character, a literal currency character, and a fixed-point number — with a single `formatMoney` call passing `{ showSign: true }`. Pass the signed delta directly; do not take an absolute value and do not branch on the sign yourself. `showSign` emits a plus for non-negative amounts and the formatter already emits a minus for negative ones, which is precisely the behavior these four sites hand-roll today.

    `ModifierSheet` currently has two branches (one for a positive delta, one that negates a negative delta). Both collapse into one `formatMoney(modifier.priceDelta, { showSign: true })` call. If the surrounding conditional exists only to choose between those two strings, collapse the conditional too; if it also controls something else (a className, a wrapper element), keep the conditional and replace only the two string expressions.

    `CartItem`, `OrderItemCard`, and `ProductForm` render the delta only when it is positive. Keep those visibility conditions exactly as they are — this task changes what is rendered, never when.

    Critical: `CartItem` and `OrderItemCard` disagree today about the unit of `priceDelta` — one divides by one hundred before display and one does not. Preserve each file's existing conversion exactly as found. That inconsistency is a real latent issue but it is out of this phase's scope, and silently normalizing it here would change a displayed amount under cover of a formatting migration. Note the discrepancy in the plan summary so it can be filed separately.

    Preserve the leading space some of these suffixes carry before the sign — it separates the delta from the modifier name.
  </action>
