# Phase 22 — UI Design Contract

> Visual and interaction contract for `EditPaidTabDialog` (correction sheet) and the `/edit-history` view. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This phase adds zero new visual primitives. It composes the existing `Sheet`, `DataTable`, `JsonDiffViewer`, `ManagerPinDialog`, `POSButton`, `QuantityControl`, `MoneyDisplay`, `Checkbox`, `Select`, `Badge` components exactly as `RefundSheet.tsx` and `AuditLogTable.tsx` already use them. This contract exists to lock in copy strings and confirm no drift from established tokens — not to invent a new look.

## Spacing Scale

Declared values (already established project-wide, confirmed via `Spacing.stories.tsx`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`) |
| sm | 8px | Compact element spacing (`gap-2`), between a row's inline controls |
| md | 16px | Default element spacing (`gap-4`, `p-4`), card/row padding — matches `RefundSheet`'s `p-3`/item-card pattern |
| lg | 24px | Section padding (`p-6`), Sheet footer padding — matches `RefundSheet`'s `SheetFooter` |
| xl | 32px | Layout gaps between major page regions |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: Touch targets on `EditPaidTabDialog`'s Confirm/PIN-submit path use `POSButton`'s `touchSize="xl"` (64px, matches `RefundSheet`'s "Request approval" button) and `touchSize="large"` (56px, matches its "Close" button) — same as the existing refund pattern, not a new exception.

## Typography

Already established project-wide (`Typography.stories.tsx`) — reused verbatim, no new sizes introduced:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-base`) | 400 (regular) | 1.5 (Tailwind default `leading-normal`) |
| Label / row copy | 14px (`text-sm`) | 500 (medium) for interactive labels, 400 for descriptions | 1.5 |
| Heading (Sheet title / section header) | 18px (`text-lg`) | 600 (semibold) | 1.2 |
| Caption / metadata (timestamps, hints) | 12px (`text-xs`) | 400, or 500 for emphasis | 1.4 |

Only 2 weights used across this phase's new UI: **regular (400)** for body/description text, **semibold (600)**/**medium (500)** for labels, headings, and the total amount — matching `RefundSheet`'s `font-semibold` refund-total row.

## Color

Already established project-wide via `src/app/globals.css` oklch CSS variables — reused verbatim:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` / `var(--card)` | Sheet body, page background, table surface |
| Secondary (30%) | `var(--secondary)` / `var(--muted)` | Item-row cards (`border p-3` blocks), disabled/fully-processed rows (`opacity-50`, mirrors `RefundSheet`'s `fullyRefunded` state) |
| Accent (10%) | `var(--primary)` | Reserved for: the Confirm/submit `POSButton` (primary variant), the selected-row checkbox fill, the active Sheet-open trigger button on the source page |
| Destructive | `var(--destructive)` | Reserved for: the required-field asterisk (`*` on Reason label), negative `MoneyDisplay` delta when the edit *reduces* the tab total, any "delete item row" affordance in the item-edit list |

Accent is NOT used for: table borders, muted metadata text, the diff viewer's neutral rows, or the "View diff" sr-only trigger — those stay on `muted-foreground`/`border` tokens per existing `AuditLogTable` convention.

## Copywriting Contract

Namespace: `featOrders` (dialog + mutation, mirrors `processRefund.*` sibling block) and `wAdmin` (`editHistoryTable.*`, mirrors `auditLogTable.*` sibling block). Both locales (`es-MX`/`en-US`) required per the committed i18n lint gate (D-05) — es-MX values below are the byte-identical-to-source convention already established in Phase 21 (genuine translation is out of scope for new keys the same way it was for existing ones; write natural es-MX copy, not machine-literal).

### `EditPaidTabDialog` (featOrders.editPaidTab.*)

| Element | Copy (en-US) |
|---------|-------|
| Sheet title | "Edit paid ticket" |
| Sheet description | "Correct items, quantities, or notes on this paid tab. Changes are recorded with your reason." |
| Reason label | "Reason" (required, asterisk — same pattern as `processRefund.reason`) |
| Reason placeholder | "Describe the correction..." (free-text `Textarea`/`Input`, not a fixed enum `Select` like refund reasons — this is an open correction, not a categorized one; RESEARCH.md's D-01 whitelist has no enum for "why," unlike refund's 5 fixed reasons) |
| Primary CTA | "Save correction" (submit button — deliberately distinct from `processRefund.requestApproval`'s "Request approval," since this flow's PIN gate happens on Confirm, then a second internal step submits; if planner keeps a two-step Confirm→PIN pattern identical to RefundSheet, CTA opens the PIN dialog, so label reads "Save correction" not "Request approval" — this is an editing action, not an approval request) |
| Secondary CTA | "Cancel" (outline variant, closes without saving — matches `processRefund.closeRefund`'s outline-button pattern but relabeled since nothing is "open" to close) |
| Loading items | "Loading items..." (identical copy to `processRefund.loadingItems`) |
| No editable items | "No items found on this tab." |
| Item quantity edited badge/hint | "Edited" (small `Badge variant="outline"` next to a row whose qty/price/notes differ from the original — new UI element not present in RefundSheet, needed so a manager can see at a glance which rows changed before confirming) |
| Add item row | "Add item" (button at bottom of item list, per D-01's "adding order_items" whitelist scope) |
| Remove item row | "Remove" (per-row destructive icon-button, per D-01's "removing order_items" whitelist scope) — pairs with a `ConfirmDialog` using the existing `confirmClassName` destructive pattern from `remove-tab-item`'s "Remove item?" precedent, not a bare click-to-delete |
| Tab-level notes label | "Ticket notes" |
| New total row | "New total" (label) + `MoneyDisplay` value — mirrors `processRefund.refundTotal` row structure exactly (`flex items-center justify-between`, `text-base font-semibold` label, `size="lg"` MoneyDisplay) |
| Total-delta hint (shown only when new total ≠ original) | "Total changes by {{amount}} — recorded as a caja adjustment." |
| No-open-caja error toast (Pitfall 4 / Open Question 2) | "No caja session is open — notes-only edits can proceed, but price/quantity changes need an open caja." |
| Generic error toast | "Could not save the correction. Check your connection and try again." (mirrors `processRefund.genericError` wording exactly, substituting "correction" for "refund") |
| Success toast | "Ticket correction saved." |
| Auth-forbidden error | "Manager approval is required to edit a paid ticket." (mirrors `processRefund.authForbidden` wording pattern) |

### `/edit-history` (wAdmin.editHistoryTable.*)

Reuses `AuditLogTable`'s shell (Pattern 3 from RESEARCH.md) — column labels below extend the existing `auditLogTable.column*` set, do not duplicate it wholesale:

| Element | Copy (en-US) |
|---------|-------|
| Page title (`PageContainer`) | "Edit History" |
| Extra column: Reason | "Reason" (reads `after.reason` per RESEARCH.md Pattern 3) |
| Extra column: Ticket / Tab reference | "Ticket" (reads `entityId`/tab short-id, so a manager can jump context without opening the diff) |
| Empty state heading | "No edits yet" |
| Empty state body | "Corrections made to paid tickets will appear here once a manager saves one." |
| Diff sheet reused as-is | No new copy — `AuditLogDetailSheet`/`JsonDiffViewer` render unchanged per RESEARCH.md ("no new table needed") |

### Destructive confirmation

| Action | Confirmation copy |
|--------|-------------------|
| Remove item row (inside `EditPaidTabDialog`, pre-save) | Title: "Remove item?" Body: "This item will be removed from the correction. This does not affect the original paid record until you save." Confirm button label: "Remove item" (mirrors `removeTabItem` copy shape, but body text is deliberately reworded — the original record isn't touched yet, unlike the live-order `remove-tab-item` feature this pattern is borrowed from) |
| Save correction (PIN gate) | No separate confirm dialog — the PIN entry itself IS the confirmation step, identical to `RefundSheet`'s "Request approval" → `ManagerPinDialog` flow. Do not add a second `ConfirmDialog` on top of the PIN dialog. |
