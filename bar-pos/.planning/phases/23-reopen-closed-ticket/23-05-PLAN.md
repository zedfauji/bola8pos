<objective>
Build the reopen-tab feature slice — the `useReopenTab` mutation hook and the
PIN-gated reason-only `ReopenTabDialog` — and wire a `ReopenTabButton` into
PaymentPane's payment-history rows so a manager can reopen a closed/paid ticket
from the same place they refund or edit it.

Purpose: This is the SC-1 user entry point and surfaces the SC-3 cap/window errors.
It reuses `useEditPaidTab`'s Result/error-mapping shape and `RefundSheet`'s
PIN-gate wiring (D-04: manager+ gate via `requiredAction='reopen_tab'`), dropping
all item-editor machinery — reopen takes only a reason, and per D-06 the result is
a fully normal open tab with no special "reopened mode" UI (the manager then edits
and re-closes it through the existing order/close/payment features, unchanged).
Output: A working, PIN-gated reopen action reachable from PaymentPane.
</objective>
