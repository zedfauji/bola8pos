<objective>
Patch every existing function that sums the `payments` table so a `reopened_void`
row no longer counts as real money. This is the phase's single highest-risk gap
(RESEARCH.md Pitfalls 3-6): introducing `payments.status` silently breaks five
pre-existing sums that assumed every non-refund payment row counts forever.

Purpose: Without this sweep, re-paying a reopened tab double-counts the voided
original (closing early or rejecting a valid partial payment), caja reports inflate
revenue, tip pooling distributes voided tips, and a manager could refund an
already-voided payment. All five are direct, unavoidable consequences of Plan 02's
new column — not scope creep.
Output: One `CREATE OR REPLACE` migration re-declaring all five functions with a
single added `status IS DISTINCT FROM 'reopened_void'` clause each. NOT pushed here
— the BLOCKING push is Plan 04.
</objective>
