## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-04 | Elevation of Privilege | new `categories` / `modifiers` joins on the service-role `admin` client | low | mitigate | The `categories` name is reached only through the existing `.eq('tab_id', body.tabId)`-scoped `orders` select, inheriting its scope. The `modifiers` query is constrained by `.in('id', ids)` where `ids` is derived solely from rows already returned by that scoped select — never from request body input. No unscoped `select('*')` and no new filter derived from user input. |
| T-25-05 | Information Disclosure | new fields on the receipt payload | low | accept | `categories.name` and `modifiers.name` are menu/catalog values already visible to every authenticated staff member on the POS product grid. No customer PII, pricing secret, or cross-tab data is added. |
| T-25-06 | Tampering | SQL injection via modifier/category identifiers | low | mitigate | All filtering uses the Supabase JS query builder's parameterized `.eq()` / `.in()` — no string-concatenated SQL, no `rpc` with interpolated text. Keep it that way. |
| T-25-07 | Denial of Service | N+1 modifier lookups on a large tab | medium | mitigate | One batched `.in('id', ids)` query for the whole tab, skipped entirely when the id set is empty (acceptance criterion asserts exactly one `from('modifiers')` call site). |
| T-25-SC | Tampering | npm/pip/cargo installs | n/a | accept | Zero package installs in this plan (RESEARCH.md Package Legitimacy Audit: N/A). |
