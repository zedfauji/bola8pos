## ⚠ Pre-existing defect discovered during planning — fixed by Task 1

`get_caja_report`'s `topProducts` subquery emits snake_case JSON keys (`product_name`) and its `staffSummary` subquery emits `staff_id` / `staff_name` / `order_count` / `sales_total`, but `CajaReportTopProductSchema` and `CajaReportStaffSchema` in `src/shared/lib/domain.ts` declare `productName`, `staffId`, `staffName`, `orderCount`, `salesTotal`. `useCajaReport` in `src/entities/caja/model/queries.ts` runs `CajaReportSchema.parse(data)`, so any caja session with at least one sale or one staff row fails to parse and the whole Caja Report returns an error Result.

This is not scope creep: this plan must add `categoryName` to that same subquery, and a camelCase field added next to a snake_case sibling still fails the same parse. The Caja Report PDF cannot be produced at all, so SC-4 cannot be verified, until the casing matches. Task 1 fixes both subqueries inside the `CREATE OR REPLACE` body it is already rewriting — a four-alias diff, no extra file.
