  <action>
    Add an exported async function `bumpTabVersion(tabId: string): Promise<number>` to `e2e/helpers/supabase.ts`, placed adjacent to `getOpenTabIdByCustomerName`.

    Behavior: obtain a service-role client via `getServiceClient()`; select `version` from `tabs` for the given id using `.single()`; throw with the Postgrest message if that errors; then update the row setting `version` to the fetched value plus 1, filtered by both `.eq('id', tabId)` and `.eq('version', currentVersion)`, with `.select('id')` appended; throw if the update errors or returns zero rows; return the new version number.

    The read-then-guarded-write shape is mandatory, not stylistic — the `bump_version_on_update` trigger rejects any `tabs` UPDATE that does not advance `version` by exactly 1, and PostgREST cannot express `version = version + 1` as a literal. This mirrors the private `bumpVersionedRows` at line 36 of the same file.

    Do not export `bumpVersionedRows` and do not refactor `resetTestState` to use the new helper — those are shipped and working.

    Document in the function's JSDoc that this simulates a second POS terminal winning the race, and that the returned value is the version the app's cached copy is now stale against.
  </action>
