## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-22 | Elevation of Privilege | New resource-insert path from the waitlist sheet | high | mitigate | No new RPC and no new policy are introduced. Insert on the relation is already restricted to manager-and-admin by the existing policy, and the waitlist page is already gated to manager-and-above, so the two align exactly. A bartender reaching this code path is rejected by RLS at the database, not by client-side gating alone. Acceptance forbids any new RPC or policy. |
| T-26-23 | Spoofing | Implicit resource creation | high | mitigate | D-05 requires an explicit click so no row is ever created as a side effect of opening a sheet or attempting a normal seat. Acceptance requires exactly one invocation site, inside the control's click handler. |
| T-26-24 | Input Validation | Number and rate on the created row | medium | mitigate | The Zod schema validates at the client boundary and the database CHECK constraints on positive number and positive rate are authoritative. The number's unique constraint additionally prevents collision with a retired floating table's permanently-consumed number; a collision surfaces as a normal error Result. |
| T-26-25 | Denial of Service | Unbounded floating-table creation | medium | accept | Each explicit click by an authorized manager creates one row, and retired rows are soft-deleted and hidden rather than removed, so numbers climb monotonically. D-03 explicitly chose simplicity here; no rate limit or number reuse is in scope. Recorded rather than silently ignored. |
| T-26-26 | Tampering | Locale key drift between the two catalogs | medium | mitigate | A key present in one locale and missing in the other renders a raw key string to the user. The Task 2 verify gate compares flattened key sets in both directions for every touched namespace. |
| T-26-27 | Information Disclosure | Visual confusion between temporary and permanent tables | medium | mitigate | The badge marker makes a floating table identifiable at a glance, so staff do not treat a self-retiring table as permanent. | T-26-28 | Tampering | E2E test residue in a shared project | low | mitigate | The new cases follow the spec's existing teardown and assert no exact table number, so residue from prior runs cannot make a later run pass or fail spuriously. |
