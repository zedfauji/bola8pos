<objective>
Establish the contract layer every downstream Plan 24 slice depends on: register the
new `order_item.remove` audit action, extend `HourlyRowSchema` (D-04) and add the four
new report-row Zod schemas (D-05/D-08/D-09), and seed all new i18n keys for both locales
so no later widget/dialog/page plan has to touch a catalog file (avoids cross-wave
catalog conflicts).

Purpose: This is pure contract/type work with zero runtime behavior. Registering the
audit action FIRST is mandatory — the `remove_tab_item` migration (Plan 04) calls
`record_audit('order_item.remove', ...)` and the `audit-actions.test.ts` CI grep gate
fails if the literal is not enumerated before the migration references it. Centralizing
all new i18n keys here means Plans 02/07/08/09/10 only call `t()` with keys that already
exist in both `es-MX` and `en-US`.
Output: Extended audit enum, extended/new Zod schemas, ~20 new i18n keys × 2 locales.
</objective>
