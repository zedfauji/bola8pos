# Phase 24 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds **zero new visual primitives**. It extends an already-mature Reports design system (`ReportsPage`, `DataTable`, `EmptyState`, `MoneyDisplay`, `ExportButtons`, Recharts) with 4 new report tabs, 1 extended tab, and a 3rd export format. Every rule below is either lifted directly from existing report widgets (`ComboMixReport`, `HourlyBreakdownPanel`, `VoidRefundPanel`) or is a new phase-specific decision built to match their conventions exactly. Do not introduce new spacing/color/typography values — reuse what's cataloged here.

## Spacing Scale

Declared values (must be multiples of 4) — pre-existing project scale, confirmed via `tailwind.config.ts` + observed widget usage, not redeclared:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (`gap-1`, `mr-2` on button icons) |
| sm | 8px | Compact stacks inside cells |
| md | 16px | `PageContainer` padding (`p-6`≈24px actually — see below), card/table cell padding, `space-y-4` between toolbar/chart/table blocks (the established report-widget rhythm) |
| lg | 24px | `PageContainer` outer padding (`p-6`), `space-y-6` page-level stack |
| xl | 32px | not used in this phase |
| 2xl | 48px | not used in this phase |

Exceptions: none. Every new report widget's root wraps children in `<div className="space-y-4">` — this is the mandatory top-level spacing for all 5 new/changed widgets (matches `ComboMixReport`, `HourlyBreakdownPanel`).

## Color

Pre-existing OKLCH grayscale system (`src/app/globals.css`) — this is a **grayscale-dominant admin surface**, not a 60/30/10 hue system. Declared as-is:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` (near-white / near-black by system theme) | Page background |
| Secondary (30%) | `var(--card)` / `var(--muted)` (`oklch(0.97 0 0)` light / `oklch(0.269 0 0)` dark) | Table zebra-free surface, callout-row background (`bg-muted/30`) |
| Accent (10%) | `emerald-500` (`text-emerald-500` / `border-l-emerald-500` / `bg-emerald-500/5`) | **Reserved exclusively for "peak"/"top-ranked"/"busiest" row and bar highlights** — established precedent in `HourlyBreakdownPanel` (peak hour) and `ComboMixReport` (top revenue row). This phase's peak-hours bar chart and payment-methods/modifier-popularity top row reuse this exact token — do not invent a new highlight color. |
| Secondary semantic (warning-adjacent) | `amber-400` (`text-amber-400` / `border-l-amber-400` / `bg-amber-500/5`) | Reserved for "slowest"/lowest-ranked row — established in `HourlyBreakdownPanel` (slowest hour). Not used for errors. |
| Destructive | `var(--destructive)` | Not used by new widgets this phase (deletions/voids are informational, not blocking actions) |
| Chart series | `var(--chart-1)` … `var(--chart-5)` (grayscale ramp) + `emerald-500` reserved for the #1/top series only | Payment-methods pie slices, modifier-popularity bars — reuse `ComboMixReport`'s existing `CHART_COLORS` array verbatim (see Chart Contract below) |

Accent reserved for: the single highlighted "top" data point per chart/table (busiest hour bar, #1 payment method slice if a "leading method" callout is added, top modifier row) — never for buttons, links, or general interactive chrome. Buttons stay `variant="outline"`/`variant="ghost"` per existing `ExportButtons`.

## Chart Contract (Recharts)

Applies to `hourly` (extended), `modifier-popularity` (new), `payment-methods` (new). Copy `ComboMixReport`'s `CHART_COLORS` constant and `chartColor()` helper verbatim into each new widget file (no shared chart-color util exists yet — do not create one this phase, 3 call sites doesn't justify extraction per YAGNI; note for a future phase if a 4th consumer appears):

```
const CHART_COLORS = [
  'var(--chart-1)',
  'oklch(0.72 0.19 145)', // --pos-accent green for top series
  'var(--chart-3)',
  'var(--chart-4)',
  'var(--chart-5)',
];
```

Rules:
- `ResponsiveContainer` height: `300` (matches `ComboMixReport`) for bar/pie; `280` acceptable for the horizontal bar chart if 20 rows need more vertical room — do not exceed `400` (keeps the tab scannable above the table without scrolling on a 1080p viewport).
- Every chart wrapped in `<div className="rounded-lg border p-4">` (exact class string from `ComboMixReport`) — this is the only chart-container treatment in the codebase, reuse it unchanged.
- `Tooltip` and `Legend` always present (both existing consumers include them; omitting either is a regression from established pattern).
- The "top" series/bar/slice (busiest hour, #1 modifier, leading payment method) is the only accent-colored element — every other series/bar/slice uses the grayscale `--chart-1`/`--chart-3`/`--chart-4`/`--chart-5` ramp. Never assign the accent green to more than one data point per chart.

## CSV Export Contract

- CSV is a **3rd item in the existing `ExportButtons` dropdown**, not a new button/toolbar element. `DropdownMenuContent` gains one `DropdownMenuItem` (`exportReport.csvOption` = "CSV") after the existing PDF item, on **every** `reportType` branch (all 17, per D-12) — including `combo-overrides` which currently has PDF disabled; CSV still applies there since PDF-unsupported ≠ CSV-unsupported.
- Same disabled/loading affordance as Excel/PDF: `Loader2` spinner replaces `Download` icon on the trigger button while `isExporting` is true, whole dropdown disabled during export — zero new loading-state UI.
- Same success/error toast copy (`exportReport.successToast`/`exportReport.errorToast`) — CSV shares the toast strings, no CSV-specific copy needed.
- Same file-save flow: `save()` dialog with `defaultPath: report-{ISO date}.csv`, `filters: [{ name: csvLabel, extensions: ['csv'] }]` — mirrors the existing `xlsx`/`pdf` branch exactly, only the extension and MIME label change (`exportReport.csvFileLabel` = "Archivo CSV" — new key, sibling to existing `excelWorkbookLabel`/`pdfDocumentLabel`).
