<objective>
Ship the generic CSV export (D-11) and wire it onto all 17 report tabs (D-12), and
extend the two hourly exporters for the new HourlyRow shape (D-04). CSV is a 3rd
`DropdownMenuItem` in the existing `ExportButtons` dropdown — not a new toolbar — reusing
the exact `save()`/`writeFile()` file flow the Excel/PDF branches already use.

Purpose: SC-2 requires one reusable CSV serializer across every new AND existing report
widget. Building one generic `rowsToCsv<T>(rows, columns)` (reusing `xlsx`'s own
`json_to_sheet` + `sheet_to_csv`, zero new escaping code, zero new dependency) and passing
each report's already-fetched rows is the whole feature. The "17 tabs" resolves to: the 12
report types that already have an ExportButtons toolbar, PLUS `tip-split`
(TipBucketDistributionPanel currently has NO toolbar — this plan adds one, CSV-only, to
satisfy D-12's "no inconsistent toolbar"), PLUS the 4 new report types the later widget
plans will consume.
Output: csv.ts + test, 17 `-csv` export branches, a CSV dropdown item on 17 report types,
D-04 hourly-exporter extension.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → Tauri filesystem | CSV bytes are written to a user-chosen local path via `save()`/`writeFile()` |
| already-fetched rows → serializer | The serializer transforms only data the widget already holds; it cannot fetch or widen scope |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-24-02-I | Information Disclosure | CSV export of report rows | low | accept | CSV serializes only the rows the widget already rendered; export cannot expose data the caller could not already see on screen. `/reports` is gated at `view_reports` (manager+) upstream, so CSV inherits that gate — no new exposure surface. |
| T-24-02-T | Tampering | CSV injection (formula-prefixed cell, e.g. leading =/+/-/@) | low | accept | Output is a passive `.csv` opened by the operator's own spreadsheet app on a single-tenant desktop POS; there is no untrusted-recipient distribution path. xlsx's `sheet_to_csv` handles RFC-4180 quoting. Formula-injection hardening is out of scope (no external consumer) — documented, not mitigated. |
| T-24-02-SC | Tampering | npm installs | low | accept | No new packages; reuses already-installed xlsx (CVE-accepted per Phase 11 decision record). |
</threat_model>
