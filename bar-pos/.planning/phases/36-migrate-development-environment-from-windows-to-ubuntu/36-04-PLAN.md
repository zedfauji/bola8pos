The phase gate. Everything automatable was verified inside plans 36-01 through 36-03; this plan collects the three checks that are inherently visual or human-judgement, and routes the pre-existing blockers that this migration uncovered.

Purpose: D-03 states plainly that browser-only `npm run dev` is not sufficient — the native shell must actually run. No automated assertion exists for "a native window opened and rendered", and building GUI-window-detection tooling for a one-time environment migration would be disproportionate machinery. 36-VALIDATION.md records this as a deliberate manual-only verification, not an oversight.
Output: human sign-off plus a recorded decision on the pre-existing blockers.

## Why a decision checkpoint is here

Three blockers surfaced during this phase that are **pre-existing and OS-independent**. None was caused by the Ubuntu migration, none is inside any D-XX decision, and each would silently expand this phase if fixed here. They need an owner:

1. **Workflow directory.** `.github/workflows/` sits at `bar-pos/.github/workflows/` while the git root is `bola8pos-kiro/`. GitHub Actions only reads `.github/workflows/` at the repository root, so neither `ci.yml` nor `release.yml` currently runs. Relocating them would also activate `release.yml`'s Windows code-signing job for the first time, which conflicts with D-04's instruction to leave the release pipeline alone.
2. **Typecheck is red.** `npx tsc --noEmit` fails with 2 errors: `src/entities/tab/model/queries.ts:791` (`Type 'number | null' is not assignable to type 'number | undefined'`) and `src/shared/lib/agent/rag.ts:60` (`Type 'number[]' is not assignable to type 'string'`). This blocks `npm run build`, therefore `npm run tauri build`, therefore the new CI job and the existing `quality` job.
3. **Git hooks are inert.** `.husky/` is gitignored so hooks are absent from a fresh clone; `core.hooksPath` holds a stale absolute Windows path; husky v9 cannot self-install from `bar-pos/`. Activating hooks additionally requires blocker 2 to be fixed first, or every commit in the repo would fail.

None — this plan creates no files and modifies none. It produces sign-off and a recorded decision.
