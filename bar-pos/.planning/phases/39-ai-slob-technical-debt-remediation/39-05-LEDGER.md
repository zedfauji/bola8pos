## Verdict on 39-RESEARCH.md Assumption A2

**CONFIRMED, with a real regression uncovered underneath.** A2 claimed many of the 53 skipped tests are stale `'UI not implemented'` placeholders for now-shipped features that un-skip cleanly. Across this batch's un-skips and re-runs:

- Several skips (18-updater:23, 19-caja-entries CE6/CE7, 20-error-scenarios ER2/ER4/ER7, 21-product-management PM2/PM3/PM5, 22-staff-management SM1/SM4/SM5) were genuinely stale **selector/harness** problems, not missing features — the underlying feature existed and worked once the test's own selectors/waits/navigation were corrected. This confirms A2's core mechanism.
- But `18-void-order.spec.ts` V2 — the one finding in this whole batch that actually drives void-order's full happy path (fill reason, click confirm) — un-skipped cleanly past its harness bug (seed-shift-selection fix) only to hit a **real, previously-hidden product bug**: `callVoidOrder` fetches a relative URL (`/functions/v1/void-order`) instead of an absolute one, so the network call 404s in every non-proxied environment and the void never actually completes server-side. This is exactly 39-RESEARCH.md Pitfall 4's warning realized in practice — "the feature exists" (void-order is CLAUDE.md-documented as shipped) did not mean "this exact flow still works end-to-end." Filed as a todo (`2026-08-05-void-order-close-shift-generate-report-use-relative-fetch-url-always-404.md`), not fixed inline (D-03) — see `18-void-order.spec.ts` V2 row.
- A2 does NOT explain everything: several failures were genuine infra (PGRST205 `pool_tables` schema-cache breakage, same root cause 39-02-LEDGER.md already confirmed) unrelated to stale skip text, and two were confirmed real access-control regressions (`21-product-management.spec.ts` PM8, `22-staff-management.spec.ts` SM6) that a test-run correctly exposes once its own timing/navigation bugs are fixed.
