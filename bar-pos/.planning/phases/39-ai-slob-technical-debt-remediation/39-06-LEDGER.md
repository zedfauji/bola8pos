## Environment setup note (methodology transparency)

Same gap as every prior Track A plan: this worktree started with no `node_modules`, no `.env.local`, and no `.audit-tmp/` (all gitignored, worktree-local). `node_modules` was symlinked and `.env.local` copied from the main checkout (`/mnt/ai/bola8pos-kiro/bar-pos/`) — same machine/user/project credentials, neither committed. `.audit-tmp/e2e-per-spec/*.json` for this plan's 6 specs was read directly from the main checkout's path rather than symlinked (a symlinked `.audit-tmp` directory doesn't match the `.audit-tmp/` gitignore pattern by type, so it was read via absolute path instead and never staged).

**Parallel-execution caveat:** this plan ran concurrently with sibling worktree agents (39-04, 39-05, 39-07) executing other Track A plans against the *same* live remote Supabase project. All specs in this batch mutate shared global state (`caja_sessions`, `tabs`, `resources`/`pool_tables`) via `resetTestState()`/`openCaja()`. One transient failure during the final live re-run (`seedTabWithBudweiser: no open caja` on a first attempt, self-healed on Playwright's built-in retry) is consistent with a sibling agent's concurrent `resetTestState()` call landing between this run's `openCaja()` and the next test's read — noted here for transparency, not classified as an app or harness defect.
