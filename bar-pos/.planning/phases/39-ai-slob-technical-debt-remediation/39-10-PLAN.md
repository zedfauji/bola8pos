<objective>
Remove the still-reported dead declarations in the `entities/` layer, one declaration at a time.

After plan 39-08 settles the barrel question, the residual `src/entities/` work is the layer's non-barrel findings — at planning time roughly 175 findings across about 46 files, concentrated in `model/types.ts` files (type aliases nothing imports), with a tail in `model/store.ts`, `model/queries.ts`, and a couple of `ui/` components. These are the phase's most mechanical deletions: the file stays, one exported declaration goes.

Two things keep it from being purely mechanical. `src/entities/inventory/model/store.ts` carries a duplicate-export pair (`inventoryStore` and `useInventoryStore` exporting the same value under two names), which is a different defect requiring a different judgment. And the same file sits inside the codebase's one madge circular import, which this phase is explicitly not chartered to fix — so the deletions here must not be turned into a refactor.

Purpose: clear the entities layer's dead declarations without deleting a file or touching the barrel contract 39-08 just settled.
Output: per-finding dispositions and a green toolchain.
</objective>

| Zustand store / query-key factory -> feature and widget consumers | Selectors and key members are frequently reached as object properties rather than as named imports, invisible to a name-only search. |
