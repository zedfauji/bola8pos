<objective>
Make printed receipts, pre-cheques, and exported report PDFs follow the acting staff's locale (D-06), and eliminate the hardcoded-label duplication between Rust `printer.rs` and TS `receipt-format.ts` by moving ALL label selection into TypeScript (RESEARCH Pitfall 2 / Assumption A2 recommended approach). Rust's `print_receipt` becomes label-free: it accepts pre-formatted `lines: string[]` and only ESC/POS-encodes them.

Purpose: D-06 requires receipts/PDFs to render in the logged-in staff's `profiles.locale`. Today the labels live in TWO hand-synced places (Rust literals + TS literals) that already disagree (the final receipt is English, the pre-cheque in the SAME TS file is Spanish). Teaching Rust to translate would add a THIRD parallel table. Instead, TS (which has i18next after 21-01) builds the fully-translated lines and Rust just encodes bytes. Non-component call sites (`i18n.t()`, `getCurrentLocale()`) are required because receipts/PDFs render outside the React `<I18nextProvider>` tree (RESEARCH Pattern 3 / Anti-Pattern).

Confirmed safe (RESEARCH Open Q3): `printer.rs` has NO `#[cfg(test)]` block and no other Rust test references `ReceiptPrintDto`/`build_receipt_lines`, so the signature change breaks no Rust tests.

Output: locale-aware `receipt-format.ts` (thermal + pre-cheque); `printer.rs` reduced to byte-encoding (`print_receipt(lines)`); `pos-printer.ts` building translated lines; locale-aware `pdf.tsx`; `receipt` catalog populated. Implements D-06, contributes SC-2/SC-4.
</objective>
