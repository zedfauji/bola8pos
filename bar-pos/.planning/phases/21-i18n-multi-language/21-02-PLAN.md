<objective>
Add the `profiles.locale` preference end-to-end: idempotent DB migration ([BLOCKING] push) + a `set_own_locale` self-service RPC + regenerated/transcribed types, `LocaleSchema` + a required-with-default `locale` field on `StaffSchema`, `mapStaffRow` carrying it through, BOTH write-path mutations (self + admin, audited), the staff-store hydrate that drives `i18n.changeLanguage()` from `profiles.locale` (D-01/D-02, never `navigator.language`), the typed `getCurrentLocale()` accessor, and the V4/T-21-02 RBAC guard integration test.

**Two write paths (this is load-bearing, discovered against the live RLS):** Phase 13's `profiles_update_admin` policy (`20260510000001_rls_rewrite_phase13.sql`) gates EVERY `profiles` UPDATE behind the `manage_staff` action. That correctly enforces the admin path server-side — but it also blocks a bartender from updating their OWN row via a direct UPDATE, which would break D-03/UI-SPEC self-service (bartenders are locked IN scope). The codebase already solved this identical problem for `must_change_pin` with a `SECURITY DEFINER` self-RPC (`clear_must_change_pin`, in `20260703000005_force_pin_change.sql`). So:
- **Self-service (21-03):** `useMutationSetOwnLocale({ locale })` → `set_own_locale(p_locale, p_terminal_id)` SECURITY DEFINER RPC that updates ONLY `auth.uid()`'s own `locale` column (no target-id param — cannot touch another user, cannot touch `role`/`pin`). Any authenticated staff may call it.
- **Admin (21-04):** `useMutationUpdateStaffLocale({ staffId, locale })` → direct `UPDATE profiles ... WHERE id = staffId`, gated server-side by the existing `manage_staff` `profiles_update_admin` RLS (no new policy needed — the enforcement already exists and is now tested).

Purpose: This is the data spine of the phase (SC-2). The two write surfaces (21-03 self-service, 21-04 admin) and the receipt/PDF locale (21-05) all consume the schema, mutations, and accessor created here. Driving `changeLanguage` from the staff record — not the browser/OS locale — is essential on a shared kiosk terminal where multiple staff clock in/out on one machine (RESEARCH Pattern 2 / Anti-Pattern).

Output: live `profiles.locale` + `set_own_locale` RPC; `LocaleSchema`/`Locale`; `StaffSchema.locale` (`.default('es-MX')`, Pitfall 4); `mapStaffRow` + mock updates; `useMutationSetOwnLocale` + `useMutationUpdateStaffLocale`; store hydrate on login + rehydrate; `getCurrentLocale`; RBAC guard integration test. Implements D-01, D-02; server-side foundation for D-03's two paths (V4/T-21-02).
